# マップ拡張：機能と段階の計画（レビュー用）

KN マップの作者が NatureFX の表現（草・光・素材・天候など）をマップ側から指定できるようにする計画です。
書式の細かい仕様は [map-authoring.md](map-authoring.md) にあります。この文書は「何を、どの順番で、どういう作りで」作るかをまとめたもので、訂正・追加・判断が必要な点を洗い出すためのものです。

> 2026-10-29 時点。**実装済み**は「コードを書いてビルドが通った」という意味で、ゲームでの確認はまだです。

---

## 1. 目的と前提

- **目的**：NatureFX が名前から推測している見た目を、マップ作者が意図どおりに指定できるようにする。マップに無いもの（街灯の光、立体の草、水たまりなど）も足せるようにする
- **対象**：まず自分の KN マップ（map generator で生成）。公式コースにも、設定ファイルの座標指定で足せるようにする
- **守ること**
  - Kino のタグ（`road_` `alpha_` `nocol_` など）を変えずに足せること
  - NatureFX を入れていない人には、何も見えない・何も変わらないこと
  - 利用者が F8 で変えた値は、マップの指定より優先すること
  - マップ作者が自分で素材（テクスチャ・モデル）を用意しなくても、NatureFX のプリセットで済むこと
  - 指定はすべてマップのデータに入れられ、別のファイルを配らなくて済むこと

---

## 2. 全体の作り（アーキテクチャ）

### 2.1 マップのデータに持たせる（Mod がなくても副作用なし）

Kino Content SDK のマップのビルドは、シーンを削らずにそのままアセットバンドルにします。そのため、標準のコンポーネントと名前だけで、NatureFX 用のデータをマップに入れられます（詳しくは [map-authoring.md](map-authoring.md) の 0 章）。

| 入口 | 置き方 | 向いている用途 | 状態 |
|---|---|---|---|
| **プロファイル（マップの中）** | `nfx_profile` オブジェクトの TextMesh の `text` に全文。描画はオフ | 素材・発光・ルール・初期値・植生の指定。配布するマップ | 読み取りを実装済み |
| **プロファイル（マップの外）** | `kino/config/NatureFX/maps/<シーン名>.nfx`。両方あればこちらを優先 | 公式コース、OBJ のマップ、手元での調整 | 一部実装 |
| **空のオブジェクト** | `nfx_<種類>_<プリセット>`。Transform が位置・向き・大きさ | ゾーン、水たまり、霧の範囲、プリセットの光源 | 読み取りを実装済み |
| **無効にした標準のコンポーネント** | Light / Reflection Probe / Decal Projector / Local Volumetric Fog / Particle System を無効にして置く | エディターで見た目を作り込みたい光や霧。NatureFX が条件に合わせて有効にする | 読み取りを実装済み（有効にする処理は段階 2・5） |
| **MeshFilter だけのメッシュ** | `nocol_nfx_grass_*` `nocol_nfx_water_*`（MeshRenderer なし） | 草を生やす面、水面 | 読み取りを実装済み（使うのは段階 4・5） |
| **頂点カラー** | R：風の強さ、G：揺れの位相、B：硬さ、A：空の開け具合 | 草木の揺れ方、屋根の下に雪を積もらせない | 未実装 |
| **メッシュのマーカー**（OBJ のマップ向け） | `nocol_nfx_<種類>_...` の透明な直方体。向きは名前のキー | OBJ だけで作るマップ | 読み取りのみ実装 |

**使わないもの**：自作のスクリプト（ゲームにコードがないため警告が出て、データも読めない）、TextAsset の単体（シーンのバンドルにはシーン以外を入れられない）

### 2.2 読み込みの流れ

```
シーン読み込み（SceneManager.sceneLoaded）
  └ 2 秒待つ（KN マップは複数のシーンを続けて読み込むため、まとめて 1 回にする）
      └ NatureFXMod.RescanAfterDelay
          ├ MapProfile.Load        … マップの外の .nfx を探し、なければマップの中の nfx_profile を読む（予定）
          │   └ 変わったら：MaterialReplacer.RestoreAll → MaterialProfiles.Load → MaterialReplacer.LoadRules
          ├ MarkerScanner.Scan     … nfx_* / nocol_nfx_* のオブジェクト（無効のものも）と [markers] を集める
          └ MaterialReplacer.Apply … シェーダーを差し替え、マテリアルに _NFX_Material* の値を書く
毎フレーム
  └ MaterialProfiles.UpdateGlobals … 太陽の高さ（_NFX_Lights）を渡す。発光の点灯に使う
```

### 2.3 シェーダー側

- NatureFX のシェーダーは HDRP/Lit のコピーです（`Editor/GenerateNatureFXShaders.cs` が自動生成）
- マテリアルごとの値（`_NFX_Material` `_NFX_Material2` `_NFX_Emission` `_NFX_EmissionParams`）は、HDRP のマテリアル用の定数バッファ（`UnityPerMaterial`）に入れています。SRP Batcher のまとめ描画が崩れないようにするためです
- 素材の経年変化・水滴・発光の計算は `ShaderLibrary/NFX_MaterialProfile.hlsl`
- `[materials]` や `[emissive]` に当てはまった `HDRP/Lit` のマテリアルは、置き換えルールがなくても `NatureFX/LitAccumulation` に切り替わります

### 2.4 担当クラス（予定を含む）

| クラス | 役割 | 状態 |
|---|---|---|
| `Map/MapProfile` | .nfx の読み込み、セクションごとの行の保持、ひな形の書き出し | 実装済み |
| `Map/MarkerScanner` | マーカーの名前・`[markers]` の解析、非表示 | 実装済み |
| `Map/MaterialProfiles` | `[materials]` `[emissive]` の解析とマテリアルへの書き込み | 実装済み |
| `Map/MapDefaults` | `[defaults]` を F8 の値に反映（利用者の変更は上書きしない） | 未実装 |
| `Map/WeatherZones` | `zone` マーカーと `[zone.*]` から、カメラ位置の天候を合成 | 未実装 |
| `Map/MapLights` | `light` マーカーから HDRP の光源を作る | 未実装（段階 2） |
| `Map/MapProbes` | `probe` マーカー・道路沿いの自動配置から反射プローブを作る | 未実装（段階 2） |
| `Nature/GrassRenderer` | 立体の草の GPU 描画 | 未実装（段階 4） |
| `Map/MapDecals` `Map/MapWater` `Map/MapVolumes` `Map/MapParticles` | デカール、水、局所的な霧、舞うもの | 未実装（段階 5） |

### 2.5 値の優先順位

1. 利用者が F8 で変えた値（最優先）
2. 天候ゾーンの値（カメラがゾーンの中にいるとき）
3. マップの `[defaults]`
4. NatureFX の既定値

F8 の「Use map profiles」をオフにすると、2〜3 とマップの素材・発光・ルールをすべて無視します。

## 3. 段階と状態

| 段階 | 内容 | 状態 |
|---|---|---|
| 0 | Kino のタグによる自動の振り分け、階層パスでのルール判定 | 実装済み・ゲームで確認済み |
| **1** | 設定ファイル、マーカーの読み取り、素材の指定、発光マテリアル、F8 の Map profile カード | **実装済み**。読み取りはゲームで確認済み（test_map：プロファイル `[map]` `[materials]` `[emissive]`、マーカー 8 個、マップ内のオブジェクト 10 個）。素材・発光の見た目はまだ確認していない |
| 1.5 | `[defaults]` と天候ゾーン、頂点カラー | 未実装（設定ファイルは読むが反映しない） |
| 2 | 光源マーカー、再帰反射、反射プローブ | 未実装 |
| 3 | 葉の透過光・色のばらつき、季節の色（`[foliage]`） | 未実装 |
| 4 | 立体の草 | 未実装 |
| 5 | デカール、水たまりと水面、煙・湯気・霧、生き物と舞うもの | 未実装 |
| 1.2 | マップの中のプロファイル（`nfx_profile`）、空のオブジェクト・無効にしたコンポーネントの読み取り、テスト用 knmap での確認 | **実装済み・ゲームで確認済み**（2026-10-30 の test_map のログ） |
| 並行 | map generator からの自動書き出し（JSON → MapBuilder がオブジェクトを配置） | 未実装 |

### 段階 1 の中身（実装済み）

- **設定ファイル**：`[map]`（`name` `inheritGlobalRules`）、`[rules]`（全体のルールより先に判定）、`[materials]`、`[emissive]`、`[markers]`
- **素材のプリセット**（12 種）：`asphalt_old` `asphalt_new` `asphalt_paint` `concrete` `masonry` `rock` `metal_galvanized` `metal_painted` `glass` `plastic` `wood` `soil`
  - キー：`porosity`（濡れたときの暗くなり方）`moss` `rust` `stain`（雨だれ）`wear`（色あせ・ひび）`dirt` `beading`（水滴）`retro`（段階 2 で使用）
- **発光**：`nits`（cd/m²）`k`（色温度）`when`（`night` / `dusk` / `always`）`mask`（`bright` / `alpha` / `full`）`random`（点いている割合）`flicker`
  - 点灯は太陽の高さで決め、6m 四方の区画ごとに数度ずらす
- **F8 > Tools > Map profile**：読み込み状況、件数、ひな形の作成、再読み込み、カメラ位置のコピー

### 段階 2：光（予定）

- **光源マーカー**：`sodium` `mercury` `led_street` `tunnel` `vending` `floodlight` `beacon` `lantern`。夜に点灯、ちらつき、霧の中の光の筋。描画は 64 個、影付きは 8 個まで（カメラに近い順）
- **再帰反射**：ヘッドライトの位置と向きをシェーダーに渡し、白線・標識・反射板が光を来た方向へ返す
- **反射プローブ**：マーカーまたは道路沿いに自動配置。時刻・天候が変わったら、近いものから 1 フレーム 1 面ずつ描き直す

### 段階 3：植生の色（予定）

- `[foliage]` で木の種類（針葉樹・広葉樹・竹・草）と、透過光・色のばらつき・紅葉の色を指定
- 季節で色を変える。冬の広葉樹は葉を減らす

### 段階 4：立体の草（予定）

- `grass_` の地面と `nocol_nfx_grass_<プリセット>` のメッシュの上に、GPU で草の葉を描く。風で揺れ、タイヤで倒れ、雪に埋もれる
- プリセット：`lawn` `wild` `susuki` `sasa` `moss`。カメラから 60m まで

### 段階 5：その他（予定）

- デカール（`crack` `patch` `oil` `leaves_pile` `sand` `skid` `moss_edge`）
- 水たまり（雨量で広がる）、水面（`stream` `gutter` `pond`）
- 局所的な霧（`mist` `steam` `smoke` `road_steam` `haze`）
- 舞うもの（`fireflies` `leaves` `petals` `moths` `dust` `pollen`）

## 4. 詰めるべき内容（判断が必要な点）

### 4.1 配布（方針決定：マップの中に入れる）

- プロファイルはマップの中の `nfx_profile`（TextMesh）に入れて、マップと一緒に配る。別のファイルは要らない
- マップの外の `.nfx` は、公式コース・OBJ のマップ・手元での調整用に残す。両方あれば外を優先（丸ごと置き換え）
- **確認済み（2026-10-29、テスト用マップ `test_map`、`tools/kino_sdk/NfxDataTestMap.cs`）**

| 持たせ方 | 結果 |
|---|---|
| TextMesh の長い文字列 | 5,238 文字・92 行がそのまま届いた（末尾の目印あり） |
| 空のオブジェクトの Transform | 位置・回転・拡大率がそのまま届いた |
| 無効にした Light / Decal Projector / Local Volumetric Fog | 無効のまま届いた（HDAdditionalLightData なども付いたまま） |
| オブジェクトごと無効にした Particle System | 無効のまま届いた |
| 無効にした Reflection Probe | 届いたが、**オブジェクトごと無効になっていた**（作ったときはコンポーネントだけ無効）。Kino がマップの反射プローブを止めている可能性。NatureFX はオブジェクトの有効化も行う必要がある |
| MeshFilter だけのオブジェクト | 届いた。Kino は当たり判定を付けなかった |
| 頂点カラー | 値がそのまま届いた（メッシュは読み取り可能） |
| HDRP/Lit にないマテリアルの値（`_NFX_TestValue`） | **届かなかった**。マテリアルごとの指定はプロファイルの `[materials]` で行う（今の仕様どおり） |
| 自作スクリプトの警告 | このマップからは出ていない |

- **未確認**：NatureFX を無効にした状態で同じマップを読み込み、見た目とログに何も出ないこと
- **判断が必要**：外のファイルを「丸ごと置き換え」にするか、「セクションごとに上書き」にするか

### 4.2 マーカー

- SDK のマップでは、空のオブジェクトの Transform で位置・向き・大きさを持てるので、名前のキー（`__yaw-90`）は OBJ のマップ向けの補助になった
- **判断が必要**：無効にした Light などを置いた場合と、プリセット名だけの空のオブジェクトの場合で、値の優先をどうするか（今の仕様：コンポーネントがあればその値を優先）
- **マーカーの見える化**：作者が位置を確認できるよう、F8 でマーカーの箱を表示する機能が要るか

### 4.3 静的バッチ

- Kino のマップはオブジェクトがまとめられるため、オブジェクト単位の区別（家の窓ごとの点灯、木ごとの色のずらし）ができない。今は 6m 四方の区画で代用している
- 精度が足りない場合は、頂点カラーの未使用の値やメッシュの UV2 に「オブジェクト番号」を焼き込む方式が考えられる（map generator 側の対応が必要）

### 4.4 利用者の設定との関係

- `[defaults]` を「利用者が変えていない値」にだけ反映するには、「どの値を利用者が変えたか」を覚える仕組みが要る（今の設定は値しか持っていない）
- マップを切り替えたとき、前のマップの初期値をどう戻すか

### 4.5 負荷の上限

| 機能 | 案 | 要確認 |
|---|---|---|
| 光源 | 64 個描画、影付き 8 個 | 峠の街灯の数で足りるか |
| 反射プローブ | 16 個、1 フレーム 1 面更新 | DX11 での負荷 |
| 立体の草 | 60m まで | 何本までなら 60fps を保てるか |
| デカール | 512 個 | ゲームの HDRP 設定でデカールが有効か |

### 4.6 ゲームの HDRP 設定への依存

- デカールと Local Volumetric Fog は、ゲームの HDRP アセットとフレーム設定で有効になっている必要がある。段階 5 の前に調べる
- 立体の草・水面のシェーダーは NatureFX のバンドルに入れるので、DX11 と DX12 の両方でビルドが必要（ビルド時間が延びる）

### 4.7 書式の版

- 将来書式を変えたときのために、`[map] format = 1` のような版の番号を入れるか
- マップの中のプロファイルは NatureFX の版より古いことがある（配布後に更新されない）ので、知らないキーは警告だけにして無視する方針で良いか

## 5. 関連する未解決事項（マップ拡張の外）

- **DX12 の自動露出**：DX12 だけ画面が真っ暗になる。自動露出の下限と上限を変えると映る。原因は未特定で、後回しにしている
- **DX12 のレイトレーシング GI**：DXR 1.0 方式を実装済み。バンドルのビルド待ちで、ゲームでは未確認
- **DX12 のタイヤスモーク**：CarX の計算シェーダーに DX12 版がないため、DX12 では止めている
- **木の葉が四角くなる問題**：対策は入れたが、ゲームでの確認がまだ
