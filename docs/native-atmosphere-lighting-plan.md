# 空・雲・霧・直接光を独自エンジンへ移す計画（2026-11-01）

ユーザーの方針: 「基本的に全てを物理ベースの演算にしたい」「ライトの直接光、空・体積雲・霧を独自エンジンに移行」。
HDRP は土台（物体の描画＝深度・法線・GBuffer、UI、パーティクル、後処理、露出）として残し、光と大気の計算を NFXNative に移す。

## 0. 今の仕組み（調査結果の要点）

- RT のパスは HDRP の CustomPass。`RTShadowPass`（AfterOpaqueAndSky）→ `RTReflectionPass`、`RTGlassPass`（BeforePostProcess）。
- 受け渡しは「Unity の Prepare カーネルが GraphicsBuffer に書く → `IssuePluginEventAndData(…, 3, slot)` で `Trace(kind)` → Unpack カーネルで RTHandle に戻す」。テクスチャの共有はない。トレースの種類は `TraceKind`（0 Sun … 8 Glass）。
- 定数は `cbuffer Frame`（NFXCommon.hlsli、2100 float、`kConstantSlot` 8448 バイト × 64 リング）。C# は `NativeEngine.Issue` で詰める。
- 新しいパスの足し方: `TraceKind` と `kTraceKinds`、`CreateTracePipelines` / `CreateTraceStateObjects` に `ShaderCode`、`#include`、`build_native.ps1` の dxc 2 リスト、C# の Prepare/Unpack と `Issue`。`-ShadersOnly` と Reload shaders（イベント 8）で再起動なしに差し替えられる。
- 表面データはトレースで作る（`_NFX_SurfaceAlbedo` RGBA8、`_NFX_SurfaceNormal` RGBA32F）。粗さは HDRP の法線バッファから。
- 合成（`NFX_RTShadow.shader` pass 2）は HDRP の色から「遮られた太陽の分」と「遮られたランプの分」を引く方式。直接光そのものは HDRP のまま。空・霧・雲は HDRP がすでに色バッファに描いた前提。
- 独自エンジンが知っている空の情報は HDRP の環境光の SH（7 float4）だけ。

## 1. 段階 1：空と体積雲（最優先。HDRP の雲が出ない問題もここで解消）

**物理モデル**
- 大気: Hillaire 2020（"A Scalable and Production Ready Sky and Atmosphere Rendering Technique"）。レイリー・ミー・オゾン、地球半径 6360 km、大気 100 km。
  - 透過率 LUT（256×64）と多重散乱 LUT（32×32）は太陽・天候が変わったときだけ計算。
  - スカイビュー LUT（192×108）は毎フレーム。
- 雲: 高度 1.2〜4 km の層をレイマーチ。
  - 雲の種類マップ（積雲・高層雲・積乱雲。`CloudController` で作ったノイズのマップを流用）と 3D ノイズ（Perlin-Worley の形 + Worley の侵食）。
  - 光は太陽方向へ 6 ステップの影 + 多重散乱の近似（Wrenninge のオクターブ）+ Henyey-Greenstein 2 ローブ + 粉効果。環境光は大気のスカイビューから。
  - 風: `_NFX_Wind` でマップとノイズをずらす。地上の約 2.5 倍、上ほど速い（シア）。
  - 1/4 解像度でレイマーチし、ブルーノイズのずらしと時間方向の蓄積（再投影）でフル解像度に戻す。

**独自エンジン側**
- 新しいトレース種類 `Sky`。入力は空の画素の向き（Prepare）。出力は RGBA（空の輝度と雲の透過率）。LUT はエンジン内部のバッファ（生バッファ + 自前の双線形補間）。
- 雲の 3D ノイズはエンジンが起動時に作る（128³ と 32³ の生バッファ）。
- 太陽の影に雲を入れる: `SunShadow.hlsl` の可視度に、雲の層を通る透過率（粗いマーチ）を掛ける → 雲の影が太陽の影と同じ仕組みで地面に落ちる。

**合成と HDRP 側**
- `NFX_RTShadow` の合成で、空の画素（深度 = 遠）を独自エンジンの空と雲で置き換える。
- HDRP の体積雲（`CloudController`）は切る。HDRP の物理ベースの空は環境光と反射プローブのためだけに残し、画面の空は上書きする。
- 環境光の整合: 曇ったら HDRP の環境光も暗くなるように、HDRP の空の SH の代わりに独自エンジンの空から SH を作って渡す（独自エンジン内では自前の SH を使う）。HDRP 側の環境光は、段階 3 で直接光と一緒に見直す。

## 2. 段階 2：霧（空気遠近と体積フォグ）

- フロクセル（視錐台を 160×90×64 に分割）に、霧の濃さを入れる。濃さは高さの指数分布 + マップの霧ゾーン + 天候 + 雨。
- 散乱光は太陽（RT の影つき＝今の光の筋を一般化）、雲の影、空の環境光、ランプ（RIS で数本）から。
- 透過率と散乱光を積分した 3D テクスチャで、不透明物に「色 × 透過率 + 散乱光」を掛ける。空の画素には大気の空気遠近（スカイビュー側）。
- HDRP の霧（`MapFog`、ゲームの霧）は切る。今の光の筋（`Shafts.hlsl`）はこの霧に統合する。
- **注意**: 半透明物（ガラス・パーティクル・タイヤスモーク）は CustomPass の後に HDRP が描くので、そのままでは霧がかからない。対策: 霧の 3D テクスチャをグローバルに公開し、NatureFX のパーティクルシェーダーとガラスのパスで読む。ゲーム自身の半透明シェーダーは霧なしになる（遠くのものだけ不自然になる。要確認）。
- タイヤスモークと局所フォグ（今は HDRP の Local Volumetric Fog）は、段階 2 の後半でフロクセルに書き込む形に移す。

## 3. 段階 3：直接光（太陽・月・ランプ）

- HDRP の各ライトの `lightDimmer` を 0 にして（影・体積の設定は残す）、直接光を独自エンジンで計算して足す。
  - 太陽: 面光源（角直径 0.53°）として RT の影、雲の影、大気の透過率で色が変わる。
  - ランプ: RIS（今のランプの影と同じ選び方）で 1 画素数本、RT の影つき。
- BRDF: GGX（高さ相関の Smith）+ Lambert（または Burley）、メタリック、クリアコート（車の塗装）、葉の透過。
  - 素材は HDRP の GBuffer（`_GBufferTexture0..3`。AfterOpaqueAndSky ではまだ有効か要確認）、なければ表面トレースのアルベド・法線と HDRP の法線バッファの粗さ。
- ノイズは NRD（太陽は SIGMA の影だけで足りる。ランプは REBLUR_DIFFUSE_SPECULAR か RELAX）。
- **注意（いちばん大きい副作用）**: `lightDimmer` はそのライトのすべての直接光を切るので、HDRP が CustomPass の後に描く半透明物（ガラス・パーティクル・髪・CarX の半透明シェーダー）が暗くなる。対策の候補:
  - (a) 半透明物には HDRP の光を残し、不透明物からだけ HDRP の直接光を引く（今の「引いて足す」合成を「全部引いて全部足す」に広げる。引く量の推定が要る）。
  - (b) HDRP の Light Layers で、不透明物と半透明物を分ける（ゲームのマテリアルのレイヤー設定を書き換える必要がある）。
  - 段階 3 の最初に、(a) を試作して見た目を比べる。

## 5. 進み具合と変更（2026-11-01）

- 1a 空、1b 雲（＋雲の影・時間方向のなめらかさ）、1c 環境光（独自の空から SH）、2 霧（光の筋を一般化）は実装済み。
- **段階 3 の変更**: 直接光の BRDF を独自エンジンで計算し直すのはやめた。HDRP の Lit の BRDF（GGX＋Lambert、クリアコート）はすでに物理ベースで、影はレイトレース・雲の影もある。置き換えても見た目は同じで、`lightDimmer` で HDRP の光を切ると半透明物が暗くなる副作用だけが残る。代わりに、太陽の光の色と強さを独自エンジンの大気（Sky.hlsli と同じ定数）の透過率から決めるようにした（`SunController.AtmosphereTransmittance`）。これで空・雲・霧・地面の光がすべて同じ大気から計算される。
- 残り: 鏡面反射の空（HDRP の空の反射プローブはまだ HDRP の空）、ランプの光で照らされる霧（今の霧は太陽と空の光だけ）、半透明物の霧。

## 6. 方針の拡大（2026-11-01、ユーザー）: HDRP を最小限に

「RT の機能に関係なく、すべて独自エンジンへ。HDRP は必要最低限にして、独自エンジンで高度なレンダリングを」。済み: 空・雲・星・月・3D の霧（`AtmospherePass`、RT から独立）。

ロードマップ（上から順に）:

| 段階 | 内容 | HDRP に残るもの |
|---|---|---|
| A | **不透明物の照明をすべて独自エンジンで**: G バッファ（`DrawExactSun` と同じく自前で描き直す）から、太陽/月・ランプの直接光（GGX + 拡散、クリアコート、葉の透過）、影（RT）、空の光（独自の SH ＋ GI）、反射（RT）を計算し、不透明物の色を置き換える。HDRP の照明は切らずに上書き（半透明物は HDRP の光のまま） | G バッファのラスタライズ、半透明物の照明 |
| B | 影と反射を常に独自エンジンで（HDRP のシャドウマップ・反射プローブ・SSR を切る。プローブは独自の空で撮るか不要に） | — |
| C | 局所フォグとタイヤスモークを 3D の霧へ（HDRP の体積フォグを切る） | — |
| D | 後処理を独自エンジンで（露出、トーンマップ、ブルーム、レンズ効果、被写界深度、モーションブラー） | UI |
| E | 半透明物: ガラスは独自エンジンで描き切る、ゲーム自身のパーティクル・半透明シェーダーは NatureFX のシェーダーに差し替え | — |

各段階に F8 のスイッチ（HDRP の描き方に戻せる）を付け、ゲームで確認してから次へ。

### A4 の進め方（2026-11-01）

1. **ランプごとの影マスク（実装済み、未確認）**: 独自エンジンが画素ごとに重い 4 つのランプの可視度をトレースし、HDRP の正確なランプの光（拡散＋鏡面）にランプごとに掛ける。濡れた路面の映り込みが壁越しに見える問題の根本対策。
2. **太陽・月の光を独自の BRDF で**: 行わない（SunExact が HDRP の BSDF を G バッファから正確に評価しており、同じ式の書き直しになるため）。
3. **フルリライト（実装済み、未確認）**: 合成が HDRP の画素を GBuffer3（空の光＋発光）・太陽・ランプ・残り（映り込み）に正確に分け、独自エンジンの影・空の割合・GI・独自の空で組み直す。

### D・E（2026-11-01）

- **D（実装済み、未確認）**: 露出（独自の測光と目の順応 → HDRP の固定露出）、ブルーム、トーンカーブ、色調整を独自のパスで。HDRP に残るのは TAA・被写界深度・モーションブラー・レンズフレア。
- **E（一部実装、未確認）**: ゲームの半透明のパーティクルを NatureFX/Particle に差し替え（独自エンジンの光と霧）。ガラスを描き切る部分は、ゲームのガラスのマテリアルを調べてから。
